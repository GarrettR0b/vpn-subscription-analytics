# Аналитика подписочного VPN-сервиса через HAPP

Портфолио-проект Data/BI Analyst: синтетические данные, PostgreSQL-витрины и
воспроизводимый Python-анализ сервиса, который продаёт VPN-подписки через сайт и
Telegram-бот.

> Это обезличенная реконструкция типа коммерческой аналитической задачи. Подход отражает
> реальную практику автора, но название сервиса, данные, параметры и результаты полностью
> синтетические.

## Что реконструируется

У сервиса нет собственного клиентского приложения. После оплаты пользователь получает
персональную ссылку, добавляет её в HAPP и использует уже включённые в подписку
прокси-серверы.

```text
сайт / Telegram-бот → оплата → ссылка подписки → HAPP → прокси-сессии
                              ↓
                     PostgreSQL-витрины
                              ↓
                    notebook / BI-дашборд
```

Генератор создаёт стабильное ядро из **435 постоянных платящих пользователей в месяц**.
Новые и временные пользователи считаются сверх него, а их приток и отток меняются
неравномерно по месяцам.

## Что реализовано

- связанные таблицы пользователей, подписок, ссылок, платежей, прокси-серверов и сессий;
- детерминированный генератор synthetic CSV и 23 Python-проверки качества;
- PostgreSQL loader, ограничения целостности и 9 SQL-проверок;
- витрины `analytics.mart_subscriber_activation` и
  `analytics.mart_monthly_business`;
- сверка Python ↔ PostgreSQL на уровне строк и метрик;
- выполненный notebook и автономный HTML-отчёт;
- Docker Compose для локальной базы.

## Быстрый старт

```powershell
py -3 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e ".[analysis,dev]"

.\scripts\run_week1.ps1 -Profile small
```

PostgreSQL: `postgresql://analytics:analytics@localhost:5433/vpn_analytics`.

## Ключевые определения

Новая оплаченная подписка активирована за 7 дней, если пользователь:

1. загрузил персональную ссылку в HAPP;
2. провёл не менее трёх успешных прокси-сессий;
3. пользовался сервисом минимум в два разных UTC-дня;
4. накопил не менее 30 минут защищённого трафика.

Подробности: [словарь метрик](docs/metric_dictionary.md), [модель
данных](docs/data_model.md), [последняя валидация](docs/validation.md).

## Структура

```text
config/       параметры генерации
data/         generated data и небольшие samples
docs/         бизнес-контекст, модель данных и KPI
notebooks/    выполненный анализ и HTML-версия
scripts/      сквозной запуск и сверка
sql/          DDL, витрины и SQL-проверки
src/          генератор, loader, метрики и Python QA
tests/        автоматические проверки
dashboard/    контракт будущего BI-слоя
```

Все выводы описывают симуляцию и не являются production-показателями реальной компании.
