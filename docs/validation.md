Все показатели синтетические. Контрольный профиль: `small`, seed `20260830`,
период январь–июнь 2026. Основная цепочка: Python → PostgreSQL → Power BI Import.

## Контрольные показатели

| Показатель | Значение |
|---|---:|
| Пользователи / подписки | 800 / 652 |
| Платежи / прокси-сессии | 3 033 / 34 701 |
| Стабильное активное ядро в месяц | 435 |
| Полученная выручка за период | 489 000 ₽ |
| MRR / платящие на конец июня | 89 930 ₽ / 557 |
| Новые допустимые подписки / активированы за 7 дней | 217 / 140 |
| M1 usage retention | 90 / 160 = 56,25% |
| M3 usage retention | 14 / 71 ≈ 19,72% |
| Участники эксперимента: control / treatment | 109 / 108 |
| Разность активации | +6,1247 п.п. |
| 95% ДИ разности | [−6,5791; +18,8285] п.п. |
| p-value | ≈ 0,34577 |

MRR - снимок на конец последнего выбранного месяца; выручка суммируется за период.
Retention означает возвращение к использованию. M0 - базовый уровень 100%;
незрелый возраст когорты отсутствует, измеренное отсутствие возвратов равно нулю.
Различие M1 и M3 не описывает траекторию одного и того же состава подписок.
Группы заданы чётностью индекса пользователя, преимущества treatment - генератором.
Статистика иллюстрирует расчёт на симуляции и не подтверждает эффект реальной настройки.

## Проверка перед публикацией

Gitleaks **8.30.1** проверил публичный состав файлов и все **6 достижимых коммитов**
через `--all --full-history`, с декодированием до двух уровней и маскированием секретов
в отчёте (`--redact=100`). Рабочие секреты не обнаружены. Единственное исходное
срабатывание в старом runtime проверено как SHA-256 исходного файла того же коммита;
для него сохранено точечное исключение по fingerprint в `.gitleaksignore`.

Отдельный поиск локальных путей и имени пользователя не дал находок в публичных файлах
и исторических Git-объектах. Handoff-файлы, служебный brief и локальная история выполнения
исключены из публичного состава; файлы Power BI и тесты включены. История Git сохранена.
Автоматический сканер не заменяет проверку прав доступа и секретов вне репозитория.

## Проверка Power BI

В PBIR четыре страницы и 80 визуальных объектов. Прежняя локальная приёмка от
15 октября 2026 включала просмотр четырёх страниц, переходы кнопками через Ctrl+Enter,
выбор и снятие месяца, тарифа, варианта настройки, ранней активации и канала эксперимента.
25 DAX-проверок прошли на той модели. Валидатор PBIR сообщал 0 ошибок и предупреждение
о недоступной внешней schema visualContainer/2.13.0; полнота schema-проверки ограничена.

В последующем проходе исправлений файлы Power BI и исходные generated-данные сохранены
без изменений, что проверено по SHA-256. Retention-витрина заменена в транзакции:
626 текущих строк до и после изменения совпали. Новый рендер Desktop в этом проходе
не выполнялся. Проверка всех сочетаний фильтров, Ctrl+щелчка мышью, устройств,
нагрузки и обновления модели на другом компьютере не проводилась.

При уточнении публичных формулировок изменены описание таблицы Activation Experiment
в TMDL, тексты и обозначения пустых значений в PBIR. Длинные тире заменены дефисами. Формулы,
привязки и макет сохранены. Расчёты, данные и графики notebooks сохранены;
пояснения синхронизированы с генераторами, HTML пересобраны.
В `.pbip` и `definition.pbir` добавлены отсутствовавшие ссылки `$schema` для проверки
служебных JSON-файлов; версии формата и ссылки на отчёт и модель сохранены.

После замены длинных тире просмотрены свежие снимки четырёх страниц Power BI Desktop.
Таблица Activation Experiment обновлена в текущей Import-модели: 217 участников,
control 109 / treatment 108, разность активации +6,12 п.п., p-value около 0,346.
Семь проверок отчёта и малого эксперимента прошли; Ruff и проверка diff успешны.
